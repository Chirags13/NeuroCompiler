Why Replace Static Heuristics?

Traditional compilers apply rigid, one-size-fits-all pass sequences (`-O2`, `-O3`). For instance, `-O3` aggressively unrolls loops and vectorizes across all programs, which benefits dense scientific computing (like matrix multiplication) but causes instruction cache bloat and register spilling on control-heavy code (like graph traversal or parser state machines).

NeuroCompiler replaces handcrafted compiler engineering rules with a dynamic, personalized pass-selection loop. Every source file is evaluated in real-time, building a custom optimization pass trajectory guaranteed to maximize execution speed while bounding code bloat.

Key Architectural Breakthroughs

  • Unified Shared Representation: A single $d=512$ embedding vector powers multiple downstream decision tasks simultaneously (Pass Profitability, Register Allocation Spill Risk, Loop Vectorization, and Parallelization).
  • Supervised-to-RL Action Pruning: Supervised models predict pass profitability $[0, 1]$, pruning the 100+ LLVM pass action space down to top-$K$ candidates so the RL agent converges 10x faster.
  • Dynamic Early Stopping: Unlike `-O3`, the RL agent learned when further optimization causes diminishing returns or code degradation, executing a `STOP` action to preserve compile time.

1. Feature Extractor

Extracts fine-grained program characteristics from intermediate representation without requiring full compilation.

Basic Block Count Opcode Histograms Branch Density Load/Store Ratio Cyclomatic Complexity PHI Node Density Loop Nesting Depth Memory Dependency

2. Neural Program Encoder

Transforms raw tabular statistics or Control Flow Graphs (CFG) into a dense latent state vector $z \in \mathbb{R}^{512}$.

Supported Encoders:

  • MLP Encoder: Fast 3-layer residual network for statistical vectors (0.5ms inference).
  • Graph Neural Network (GNN): Spatial graph convolution over CFG/DFG nodes for maximum topological fidelity.

3. Supervised Multi-Head

Four specialized predictors sharing the $d=512$ program embedding:

  • Model A (Pass Profitability): Sigmoid probabilities across candidate passes.
  • Model B (Spill Risk): 3-class classifier (Low / Med / High) to assist allocator.
  • Model C (Vectorization): Binary decision + Expected speedup regression.
  • Model D (Parallelization): Safety predictor + confidence interval.

4. Reinforcement Learning Orchestrator (PPO)

Treats compilation as a sequential Markov Decision Process (MDP) $\langle \mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma \rangle$:

State S_t = [ z_t || PassHistory_t || BudgetRemaining_t ]
Action A_t ∈ { Top-K Supervised Passes } ∪ { STOP }
Reward R_t = ΔSpeedup - α·ΔCompileTime - β·ΔCodeSize

Using Proximal Policy Optimization (PPO) with clipped surrogate objective to guarantee stable policy updates during multi-step optimization trajectories.

5. LLVM Pass Manager & Plugin Bridge

Integrates with LLVM's modern `NewPM` architecture via C++ pass wrappers or a custom Python-to-C++ IPC bridge (`CompilerGym` / custom `PyBind11` interface).

// Pseudo C++ Pass Injection Loop
void NeuroCompilerPass::run(Module &M, ModuleAnalysisManager &AM) {
    while (!state.isTerminated()) {
        FeatureVector fv = extractIRFeatures(M);
        Action pass_id = rl_agent_client.predict(fv);
        if (pass_id == ACTION_STOP) break;
        PassManager.runPassById(pass_id, M);
    }
}

How Supervised Learning Guarantees Fast RL Convergence

Pure reinforcement learning in compiler optimization suffers from a severe **combinatorial explosion**: with $|\mathcal{A}| \approx 100$ candidate passes and episode lengths of up to $L=20$ steps, the trajectory space exceeds $100^{20} = 10^{40}$ sequences. Pure exploration produces broken or degenerate IR sequences for thousands of epochs.

Mode 1: Action Space Pruning (Implemented)

At each step $t$, Model A (Supervised Pass Profitability) evaluates all candidate passes and emits probability $P(a_i | z_t)$. The RL agent's action space $\mathcal{A}_t$ is dynamically restricted to only the top $K=8$ passes where $P(a_i) > \tau$. This reduces the branching factor from 100 to 8!

Mode 2: Prior-Weighted Policy Initialization

The actor network $\pi_\theta(a|s)$ in PPO is initialized with a KL-divergence regularization term against the supervised distribution $\mathcal{P}_{SL}(a|s)$ during early episodes: $\mathcal{L}_{Total} = \mathcal{L}_{PPO} - \lambda \cdot D_{KL}(\pi_\theta || \mathcal{P}_{SL})$.

Mode 3: Multi-Objective Reward Shaping

To penalize redundant optimization steps before execution benchmarking completes, intermediate rewards are augmented with potential-based shaping derived from the supervised model's estimated speedup reduction vector.

Mathematical Formulation of the Reward Function

The agent optimizes a multi-criterion scalar reward $R_t$ at step $t$ (or upon terminal step $T$):

R_T = w_1 \cdot \left( \frac{T_{base} - T_{neuro}}{T_{base}} \right) - w_2 \cdot \max\left(0, \frac{C_{neuro} - C_{base}}{C_{base}} - \theta_{time}\right) - w_3 \cdot \max\left(0, \frac{S_{neuro} - S_{base}}{S_{base}} - \theta_{size}\right)

Where $T_{base}$ is execution time under `-O2`, $C$ is compile time, $S$ is binary text segment size, and $\theta$ thresholds represent acceptable overhead tolerances ($\theta_{time} = 0.15$, $\theta_{size} = 0.05$).
